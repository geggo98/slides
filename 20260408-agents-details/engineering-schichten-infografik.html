01 · Die Schichtung

Jede Schicht löst, was die darunter nicht mehr greift.

Prompt ⊂ Context ⊂ Harness. Evolution umschließt das Ganze — experimentell. Hover über eine Schicht für die Kurzfassung.

Experimentell
Evolution Engineering
Das Meta-System
Der Agent verändert sich selbst — Skills, Prompts, Memory, in radikalen Varianten sogar den Loop-Code. Potentieller nächster Schritt, nicht etablierte Disziplin.
Harness Engineering
Das System
Alles um das Modell herum: Agent-Loop, Tool-Registry, Sandboxing, Middleware, HITL-Gates, Observability. Empirisch oft wichtiger als das Modell selbst.
Context Engineering
Das Fenster
Kuration des gesamten Token-Inhalts pro Turn — System-Prompt, Tools, Retrieval, Memory, Sub-Agent-Outputs. Das Context-Window als endliche Ressource.
Prompt Engineering
Der String
Der einzelne Input und seine Struktur — System-/User-Message, Few-Shot, Chain-of-Thought, XML-Tags, Prefill. Als Jobtitel tot, als Handwerk echte Teilmenge von Context.
Prompt ⊂ Context ⊂ Harness  ·  umschlossen von Evolution (experimentell)
Intent Engineering
Nicht in der Schichtung

Taucht in Vendor-Decks auf. Meint praktisch Spec-driven Development oder klassisches Requirements Engineering — ohne eigenständige Methode, empirische Evidenz oder kanonische Referenz. Wer den Begriff nutzt, sollte meist nur präziser werden.

03 · Die Disziplinen

Was jede Schicht wirklich leistet.

Jeder Begriff mit Substanzurteil: ●●● solide · ●●○ Handwerks-Teilmenge · ●○○ experimentell · ○○○ Marketing.

/01 · PROMPT
Prompt Engineering
// Als Jobtitel tot — als Handwerk lebt es weiter

Arbeitet mit einem diskreten String. Klare Instruktionen, XML-Tags (Claude wurde explizit darauf trainiert), Few-Shot-Kuration, strukturierte CoT, Response-Prefilling, Long-Context-Anordnung.

Anthropics Position: Prompt Engineering ist nicht tot, sondern echte Teilmenge von Context Engineering — Tool-Descriptions und System-Prompts verdienen weiterhin die volle Sorgfalt.

/02 · CONTEXT
Context Engineering
// Der einzige Begriff mit klarer Neuheit

Iterative Kuration aller Token pro Turn: System-Prompt, Tools, MCP-Server, Retrieval, Memory, History, Sub-Agent-Outputs. Das Window ist endliche Ressource.

Empirischer Schmerzpunkt: Context Rot. Recall degradiert mit Länge — bei 1M-Fenstern oft schon ab ~256k. Jentic-Daten: Tool-Selection fällt von 43% (<10 Tools) auf 14% (>50 Tools).

Kernpraktiken: Compaction, Structured Note-Taking, Sub-Agent-Isolation (Anthropic) · Write/Select/Compress/Isolate (LangChain) · Just-in-Time Retrieval statt Upfront-Load.

Geprägt
18. Juni 2025 · Tobi Lütke
Kanon
Anthropic · Karpathy · LangChain · Willison
Scope
Das gesamte Context-Window
/03 · HARNESS
Harness Engineering
// Die jüngste, aber sauber motivierte Ebene

Modell = CPU · Context = RAM · Harness = OS · Agent = Applikation. Agent-Loop, Tools, Sandboxing, Middleware, HITL, Observability.

Empirie: LangChains deepagents-cli sprang von Platz 30 auf Platz 5 auf Terminal Bench 2.0 ohne Modellwechsel — nur Harness. Cursor hat Vollzeit-Engineers für Prompts und Tool-Descriptions pro Modell-Release.

Fowler/Böckelers Guides-and-Sensors-Matrix: computational (Linter, Tests) × inferential (LLM-Judge, AI-Review) bilden vier Quadranten.

/04 · INTENT Marketing
Intent Engineering
// Kein eigenständiges Feld

Taucht auf bei Cloud-Vendors, in GitHub Spec-Kit-Kontext (Oktober 2025), in Karpathys „Software 3.0"-Reden. Ihm fehlt alles, was Context und Harness tragen: Abgrenzungskriterium, Community, empirische Evidenz, kanonische Referenz.

Substanziell sind die Nachbarn, auf die verwiesen wird: Spec-driven Development, Requirements Engineering, Willisons Kritik am „vibe coding". „Intent Engineering" addiert nichts über diesen Kanon hinaus.

/05 · EVOLUTION Potentieller Nächster Schritt
Evolution Engineering
// Wenn der Agent zum Harness-Engineer wird

Sobald der Agent Teile seines Harness anpasst, wird er selbst zum Harness-Engineer — bei Hermes auf Skills- und Memory-Ebene, bei DGM auf Python-Code-Ebene. Theoretisch interessant, praktisch riskant.

Das Spektrum reicht von self-improving light (Hermes: Markdown-Skills, PR-Gate für Code) bis zur radikalen Gödel-Machine-Tradition (Monkey-Patching, evolutionäres Archiv). Safety-Gates bilden die entscheidende Achse.

Dokumentierte Failure-Modes: Reward Hacking (DGM lügt über Test-Resultate), Skill-Junk-Drawer (redundante, vage Skills), Goodhart-Effekte. Gates sind nur so gut wie die Metriken dahinter.

Praktisches Urteil: Für Produktionscode bleibt Harness Engineering mit Guides-and-Sensors-Disziplin sinnvoller als jede Self-Evolution-Träumerei. Aber die Richtung ist ernst zu nehmen.

04 · Evolution im Detail

Sieben Systeme, zwei Achsen.

Der Agent schreibt sich Markdown-Prozeduren, nicht seinen Python-Code. Skills entstehen nach komplexen Tasks durch Reflection (typisch ≥5 Tool-Calls), landen in ~/.hermes/skills/, werden bei erneuter Nutzung verfeinert. Radikale Code-Modifikation ist bewusst in hermes-agent-self-evolution ausgelagert und durchläuft dort PR-Gate plus menschliches Review. Approval-Policies für destruktive Commands sind default aus — wer das produktiv einsetzt, schaltet sie aktiv ein und nimmt Container-Backends statt local.

05 · Fazit

Was bleibt, was fällt.

Das idiomatische Denken: Probleme der richtigen Schicht zuordnen. Tool-Fehlauswahl ist selten ein Prompt-Problem, häufiger Context, manchmal Harness.

Bleibt
Context Engineering

Benennt präzise eine Systemebene, die Prompt Engineering strukturell nicht erreicht. Industrie-Adoption (Anthropic, LangChain, Shopify), empirische Grundlage (Context Rot), klare Abgrenzung. Willisons Juni-2025-Prognose „sticking power" hat sich bewahrheitet.

Etabliert sich
Harness Engineering

Benennt, was Cursor, Claude Code und SWE-agent tatsächlich tun — Systems Engineering ums Modell. Jung, aber fundiert (Fowler, LangChain, Codex-Report). Mit stärkeren Modellen wird Harness dünner, nicht null — analog zu „Prompt Engineering verschiebt sich, stirbt nicht".

Offen · Potentiell
Evolution Engineering

Ernst zu nehmende Richtung, aber noch kein etabliertes Feld. Hermes zeigt den konservativen Weg (Markdown-Skills, PR-Gate für Code), DGM und AlphaEvolve den ambitionierten. Die Gates sind nur so gut wie die Metriken — Reward Hacking ist dokumentiert. Für Produktion: Harness mit Disziplin vor Self-Evolution mit Hoffnung.

Marketing
Intent Engineering

Wird als Vendor-Vokabel überleben, ohne eigenständig zu werden. Wer es nutzt, meint meistens Spec-driven Development oder Requirements Engineering — dann sollte man das auch so nennen. Kein substanzieller Beitrag über den Basis-Kanon hinaus.
